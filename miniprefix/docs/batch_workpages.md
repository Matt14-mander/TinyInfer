# 批量执行前的物理页准备与 COW 工作页

共享感知准入保证活跃请求可以完成生成，但并不保证某一时刻的空闲物理页足以容纳整批 COW。
此前 prepare_batch 不回收缓存，20 页池即使有大量可驱逐缓存，也会频繁回退逐请求执行。

## 准备流程

KVManager 统一处理 CPU/CUDA 共用的页引用与空间规则，CUDA runner 沿用现有批量载荷执行：

1. 验证所有行的 ID、token、context、待恢复前缀及预约额度。未预约序列的扩页需共同保护已有预约，
   即使某行只填充尾页，也不能跳过已有容量承诺检查。
2. 计算所有扩页，加上所有引用数大于一的部分尾页 COW 目标。这里保留原源页到事务提交，
   不借用未来某行提交、结束或释放以后才会出现的空间。
3. 当前空闲页不足时，取得缓存的只读 LRU 引用顺序，在引用计数副本上逐项模拟。
   多个缓存条目可能引用同一物理页；活跃请求、待恢复准入及诊断租约仍持有引用，不能当作空闲页。
   尾页引用降到一时，可取消该行 COW 并原地追加，无须额外申请替换页。
4. 全部可回收缓存仍不足时返回空组。缓存条目、LRU、命中/驱逐计数和请求映射均不改变，
   Engine 沿用逐请求路径，不等待一个无法形成的批次。
5. 计划可行时先准备 host 元数据容量，再按当前 LRU 次序执行最少的必要驱逐。
   各 Append 事务取得新页和 COW 目标；整组准备成功后才向 GPU 提交复制和计算。

页面来自原有固定物理池，没有额外的隐式 KV 池，也没有扩大 max_blocks、放松准入或占用其他请求的未来额度。
整个接口仍是单线程同步约定；事务活动期间不能发布、清空缓存、释放序列或插入其他普通 append。

## 发布、LRU 与失败边界

准备阶段不发布历史、不调用前缀匹配 touch，也不改变 Engine 的行顺序。未 resident 请求仍在原有
边界恢复前缀，不能越过前面行的发布。缓存 victims 始终按当时 LRU 从旧到新移除，剩余节点相对顺序不变。

这是新增的**批次边界压力操作**：相对旧逐请求回退路径，驱逐可能提前发生，驱逐次数、物理页 ID 和
最终命中统计允许改变；不承诺与逐请求执行逐项同轨迹。发布调用顺序、LRU 淘汰策略、输出 token 和
已提交 KV 的正确性保持原有约定。

完整计划不足或输入/预约无效时不驱逐。计划已经应用后，失败回滚恢复请求页映射和已提交长度，释放
新页及 COW 目标；**实际发生的 LRU 驱逐效果保留**，与现有普通 append 的失败语义一致。无需保存并恢复
已经作为工作页覆盖的缓存载荷。

CUDA 必须先完成/同步设备读写再回滚；已有异常路径和 dirty 页表修复继续生效。非有限批量结果回滚
整组后逐请求重放，保留原成功/失败事件顺序。若 host 分配在应用驱逐后失败，已构造事务通过 RAII 回滚，
驱逐仍保留；没有新的失败重试循环。

## 验证与比较

- KVManager：全部输入先验证；固定页先于可释放页的 LRU；两个缓存引用仅释放一个物理页；
  无法容纳整组时零驱逐；最后缓存引用消失后取消 COW；诊断预约边界；重试与归零。
- CPU/CUDA 实际复制：混合扩页+COW 到物理池上限；在 K/V 复制中途注入失败，同步后回滚并重试，
  验证源载荷和页表不损坏。CUDA runner 另覆盖空间准备后非有限结果、整组回滚、重放和新前缀恢复。
- 现有 CPU/CUDA 全量回归及真实模型同后端无缓存参考，验证正常生成与前缀复用。

原生 capacity 基线新增 `--before-binary` 和 `--policies`，按轮交错运行修改前/后可执行文件；
汇总按 variant 分组，防止把两版本数据混到一起。模型、负载、到达 seed、缓存预算与池大小相同。

```text
python miniprefix/benchmarks/capacity.py --binary AFTER --before-binary BEFORE --model MODEL.mpf --backend cuda --rates 40 --requests 128 --repeats 3 --policies shared --output batch-workpages.jsonl.gz
```

TTFT 从计划到达计时，TPOT 为单请求输出间隔均值；计时包含主机观测，不包含 tokenizer/worker IPC。
三种缓存模式各三轮，保留吞吐范围，报告轮次分位数的中位数。达到输入需求不代表测得饱和吞吐上限。
实测结果及二进制指纹见 [验收报告](acceptance/batch-workpages.md)。
