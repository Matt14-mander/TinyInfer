# 非整页精确前缀缓存

MiniPrefix 现在缓存已提交历史的完整页及部分尾页。CPU/CUDA 使用同一个索引和容量账本，
命中后的页内追加通过已有 COW 事务隔离。缓存仍默认关闭，worker v3 和统计字段数量不变。

## 发布和匹配

Engine 在整个 prompt 的 prefill 完成、以及每次成功 decode 后，检查 logits，再发布当前已提交
KV 历史，随后交付采样 token。刚采样的 token 尚未 forward，不进入缓存。中途取消 prefill
不额外发布未完成 prompt；取消/EOS/长度结束保留此前已发布的快照。后端失败沿用 Engine 清理策略。

缓存匹配完整的因果历史，返回最长可用 token 前缀；匹配可停在缓存部分页、缓存完整页的内部，
或分叉 token 之前。最多命中 `prompt.size() - 1`，至少留下一个 token 计算 logits。例如缓存
`[1,2,3,4]`、页长 4 时，请求 `[1,2,9]` 命中 2，请求 `[1,2,3,4]` 命中 3。没有 cached-logits 路径。
增量 prefill 从精确命中位置继续，RoPE 位置与 token 预算都按实际 token 数计算。

完整页构成 trie 的中间边，部分页只作为最后一条边；每条路径包含此前全部 token。
每个节点另外维护只含有效缓存引用的有序子节点表，使用 lower_bound 及前驱比较最长公共前缀，
不扫描所有缓存项，也不把已淘汰但仍作为结构祖先的节点当作命中。相同长度命中优先选
lower_bound 候选，保证 LRU 行为确定。查找每页成本约为 `O(B log F)`，B 为页长，F 为分支数。

## 引用、LRU 和容量

不同长度的快照是独立缓存项，各持有页引用，并进入同一 LRU。重复发布同一个完整历史键只
刷新已有项，不替换 payload。部分尾页发布后成为共享页，后续追加必须 COW 或先移除最后一个
缓存引用。当前每步 decode 发布可能增加复制和快照数量；它是正确性首版，收益需另行测量。

容量上限仍以缓存项/页引用数计算；发布最多前 `prefix_cache_blocks` 页，保留有界根前缀策略。
LRU 淘汰移除查找项和一个缓存引用，仍被请求持有的物理页继续有效。多个长度快照可能共享
同一物理页：`kv_cached_blocks` 统计缓存项，`kv_cache_only_blocks` 按仅被缓存持有的物理页去重。
该统计通过每个物理块的缓存引用计数计算，查询成本为 `O(max_blocks)`；页面总物理占用仍由池计数。

请求继续独立预约最坏页数，不抵扣共享收益。准备 append 时同时考虑新增页和 COW 替换页。
每次压力淘汰后重查尾页引用数：若只剩当前请求，则取消 COW、原地追加。这样一页池中
“缓存半页 → 命中 → 补满”无需额外物理页。若其他请求仍持有尾页，则必须复制；旧引用保留
至事务成功，失败恢复原页表并回收新页。CUDA 复制及失败后的页表修复沿用上一阶段实现。

## 验证与后续

- 索引：独立平铺全历史参考实现，5 种容量共 15,000 次随机发布/查询/淘汰/clear，比较结果、
  LRU、引用、计数和最终释放；另覆盖结构祖先缺失、深路径与长短快照共享物理页。
- Engine：接受页内命中、精确 suffix 位置/预算、逐步发布、最终未计算 token、取消及失败。
- CPU/CUDA：两层 GQA 模型的 1/3/4/7/8 token 历史、同页分叉、相同 prompt、非有限 logits
  回滚、一页池容量边界；全部 logits 对独立 CPU 重算、资源归零。
- 真实模型：`verify_generation_history.py` 是当前多轮缓存验收入口，使用独立 Transformers
  FP32 全前缀 oracle，检查输出、实际跳过 token、forward 计数及 CUDA 无 KV/权重回传。

早期 `verify_prefix_cache.py` 等收益脚本中的整页命中/容量假设属于历史实验，不能直接作为
当前非整页缓存的性能基线。下一步应固定共享比例、历史长度、页长与容量，重新测量 TTFT、
吞吐、COW 字节数和快照淘汰开销，再决定减少发布频率或合并被较长快照覆盖的项。
