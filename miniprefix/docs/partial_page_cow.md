# 部分页 COW 基础能力

> 2026-10-29 更新：当前已支持[非整页精确前缀缓存](partial_prefix_cache.md)。下文保留该阶段的实现与历史验收边界；当前匹配和发布语义以新文档为准。

`KVManager::fork_sequence(source, target)` 将源的已提交 token 历史和页引用共享给已创建的空目标，
包括未满尾页。CPU/CUDA `ModelRunner` 暴露同名接口；本阶段没有新增 Engine 请求类型或 worker 命令。
`ExactPrefixCache` 仍只发布、匹配完整页，非整页前缀缓存留到下一阶段。

## 预约如何覆盖替换页

每个请求继续独立预约 `ceil(max_kv_tokens / block_tokens)` 页，**不因共享而减少预约**。
例如两个各需一页的请求共享同一半页时，物理占用是一页，但逻辑预约是两页；其中未使用的
一页额度覆盖写入分离。无需在 append 中临时扩充预约，也不预留固定额外 COW 页。

fork 目标已有预约时，源页数不得超过目标预约；无预约时，将源页数加入当前独立页数账本，
超出总容量则拒绝 fork，且不改变目标。将来新增部分前缀缓存时同样不能给预约打折。
物理分配仍会先按 LRU 淘汰缓存引用；追加需要的新页和一张 COW 替换页必须同时有空间。
这些是同一个事务的物理需求，COW 替换不增加请求最终逻辑页数。

共享尾页的旧引用在事务中暂时保留，保证回滚安全。KVManager 一次只允许一个 append 事务，
期间禁止创建、fork、准入、释放序列及缓存变更，防止释放源后再准入其他请求占用暂存额度。
`release_reservation` 仍为 noexcept，但新准入必须等事务结束。该接口仍为单线程接口。

## 复制与事务

当 `used % block_tokens != 0` 且尾页引用数大于一时，append 分配替换页并暂时修改目标页表。
`copy_shared_tail` 为每层提供元素偏移和有效 token 数，后端必须复制 K 和 V；未提交的尾部不复制。
CPU 使用内存复制；CUDA 在模型所在 stream 上先执行 D2D 复制，再上传页表、运行模型。
fork 后 CUDA 目标页表在首次 append 时完整上传。

- 成功：后端完成计算与 logits 校验后 commit，提交历史并释放旧尾页的目标引用。
- 复制或计算异常：后端先等待已排队的设备访问结束，再 rollback；恢复原尾页，释放替换页和新增页，
  不增加 used、tokens 或 forward_tokens。已经发生的缓存淘汰和传输计数不会回滚。
- CUDA 异常后页表标记为 dirty；下次 append 完整刷新，即使源已释放、尾页独占而不再触发 COW。
- 整页边界不复制旧页；独占尾页直接写入。clear/release 仍按引用计数归还页面。

后端调用方必须保证 GPU 访问完成后才提交或销毁事务。测试的可恢复异常不代表支持 CUDA
设备丢失后的恢复；Engine 对真实后端故障的现有失败策略不变。

## 回归

`miniprefix_cow_cpu_tests` / `miniprefix_cow_cuda_tests` 覆盖：

- 双请求预约耗尽总逻辑容量时，COW 与跨页追加仍能成功；额外准入等待。
- fork 容量不足拒绝且目标不变；事务期间禁止破坏旧页所有权。
- 两层 K/V 有效尾部复制、未使用区域不复制、复制第一层后注入异常、回滚重试和最终资源归零。
- 两层 GQA 小模型的非对齐/整页边界 fork，与 CPU 独立重算比较全部 logits 和 argmax。
- 后端完成复制后产生非有限 logits，检查历史/页数回滚；释放源后重试验证 CUDA 页表修复。

CUDA 测试使用真实 D2D 复制和 kernel，不用 CPU 模拟设备路径。
