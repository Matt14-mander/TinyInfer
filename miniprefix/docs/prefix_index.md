# 精确前缀索引与 LRU 优化

本次保持精确前缀复用、页面容量、KV lease、累计计数、worker 协议和保守容量预约的行为。
CPU/CUDA 共同使用同一个 ExactPrefixCache，实现仍位于 src/kv；容量协调仍归 KVManager。

## 数据结构

原实现为 `map<完整因果 token vector, Entry>`，每发布一页就复制从开头到该页的历史；
LRU 每次 min_element 扫描全部缓存条目。新实现使用按页分边的精确 trie，children 为带透明
比较器的有序 map，查询直接借用输入中的一页范围，不构造临时 vector，也不依赖 hash。
只有新建边时复制该页 token，完整路径代表相同模型/配置作用域内的完整因果 key。

缓存页节点另以侵入式双向链表维护 LRU，命中、重复发布的访问顺序不变；touch 和取最旧
缓存页为 O(1)，不再用递增 timestamp 或扫描寻找最小值。实际淘汰还可能剪掉无用祖先，
成本取决于回收节点数及 children map 操作，不能把整个 evict_one 宣称为严格 O(1)。

对于 P 页的单链前缀，边 token 内容从 B*P*(P+1)/2 降至 B*P；查找/发布沿路径执行每页
一次 children 查找，成本受页长 B 和各节点分支数影响。不是 token 级或压缩 radix tree。

## 缺页、回收和安全

- 缓存条目与结构节点分开计数。祖先被淘汰后，可以保留不带 KV lease 的节点来定位后代。
- reuse 遇到第一个无缓存页的节点就停止，不能穿过缺页去复用后代；重新发布祖先后可恢复完整匹配。
- 淘汰只移除一个缓存引用。活跃请求引用、物理页号、累计 evictions 与旧实现保持一致。
- 删除无 lease 的空叶子，并向上迭代剪枝，避免长期根前缀切换留下空路径；clear 后节点/边 token 均归零。
- 发布缺失祖先时，淘汰其最后一个缓存后代可能触发剪枝。实现保护当前发布节点，直到新引用安装完成。
- clear 按 trie 字典序预遍历释放，保持旧 map 的释放及页池 free-list 顺序；不计入 evictions。
- 所有遍历/剪枝都为迭代方式，不依赖深路径递归析构。查找与 touch 不分配索引节点；
  publish 节点分配失败不留下空路径，retain 失败会剪掉新空节点。已经发生的合法淘汰不回滚。

每个结构节点必须通往至少一个缓存节点，最长路径受 publish 的缓存容量截断约束；
共享根场景下边存储显著减少，但多条互不共享的深路径仍可能保留较多结构祖先，不能声称
所有工作负载下总 metadata 严格正比于缓存页数。`index_nodes()` 和 `key_token_bytes()`
提供诊断观测，未增加 STATS 字段；key bytes 只含 token 内容，不含 map/node/allocator。

## 验证与测量

测试保留旧实现作为 test-only reference，5 种容量（0/1/2/5/16）、每种 3,000 步确定性
随机操作，逐步比较物理页号、token 历史、引用数、命中/淘汰/复用计数及活跃页。
另覆盖缺失祖先、淘汰期间正在重新发布的节点、反复根替换、空缓存、未对齐尾页、retain 失败清理及 8,192 页深路径的非递归淘汰/clear。

原 `prefix_index` benchmark 只将 key 大小由旧公式改为实际计数，其余负载和计时范围不变。
用保存的旧二进制与新二进制交替运行三轮，每轮十个原始样本；同时进行真实 CPU/CUDA worker
差分、小页池准入、短时混合压力和全部 CTest 回归。性能结论仅针对 metadata 微基准，
不把它作为真实模型吞吐提升或新的长期 soak 结论。

本机结果、原始计时和回归证据见 [2026-10-29 索引优化验收](acceptance/prefix-index-optimization.md)。
