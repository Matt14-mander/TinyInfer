# 前缀发布与快照优化验收（2026-11-04）

同机旧/新 CUDA worker 交替执行，原样复用上一轮四类负载及 off/cold/hot 基线。
每组合 6 次正式测量、3 次独立 profiling，共 216 个样本全部通过；旧 worker 为 d670742，哈希与上一轮新 worker 一致。
所有配对样本的输出、复用/forward 数以及完整前后 STATS 均一致（包括引用资源、淘汰、上传量与分配计数）。COW 次数与字节保持一致。

## 主机元数据微基准

相同 MSVC 14.29、/O2 /MD /DNDEBUG /EHsc /std:c++17，分别链接 d670742 与当前 prefix_cache.cpp。
三轮交替旧/新进程，每轮含每场景 10 个计时组；每组 10000 次发布，另有不计入的 warmup。
表中耗时是 30 个组内平均值的中位数；分配计数仅在 publish 循环内统计。

|场景|旧/新 ns/发布|旧/新分配次数/发布|
|---|---:|---:|
|repeat|686.09 / 187.11|0.0000 / 0.0000|
|snapshots|1227.12 / 473.17|5.9904 / 0.0000|
|branches|10148.65 / 9179.42|198.0000 / 160.0000|

repeat 是 32 页相同历史重复发布；snapshots 是共享 32 页前缀的 96 个尾快照轮换；branches 是 96 个根不同的分支轮换。
源元数据事先构造并保持存活，不执行模型计算、payload 复制或 IPC。快照轮换进入稳定淘汰后可复用全部新增索引分配；此结果不表示冷缓存首次发布零分配。
优化保留所有逻辑快照。每个节点增加 depth，另保留一个非拥有路径 vector 和最多各一个空闲叶/lookup 节点；clear 释放空闲节点但保留路径 vector 容量。

## 真实模型端到端对比

SmolLM2-135M-Instruct FP32，RTX 4070 Laptop，页长 16、上下文 128、KV 64 页、缓存 32 条目、每请求输出 8 tokens。
TTFT/TPOT/tok/s 为不插桩轮次的中位数；发布 µs 为独立 profiling 中每请求 8 次发布的总耗时中位数。

多轮 hot 的发布总耗时中位数 54.3→24.8 µs，减少约 54.3%；正式 TTFT 10.629→8.909 ms、TPOT 10.283→7.872 ms、吞吐 98.73→123.83 tok/s。
但几十微秒的主机节省不足以解释毫秒级变化。off 对照吞吐比也有 1.007–1.101× 波动；identical-tail hot 与 in-page-branch cold 的配对吞吐比为 0.979×、0.966×，存在退化。
因此可以确认元数据发布与分配成本下降，不能据此宣称稳定的端到端加速或把表中的全部差异归因于该优化。
Windows/WDDM，未锁频或证明排除全部后台活动；保留所有原始样本与范围，无 p99/SLA 结论。吞吐为单请求输出吞吐，非并发饱和吞吐。
计时包含 submit/step IPC 与事件交付，不含加载、分词、warmup、hot prime 和统计查询。热缓存 prime 成本需要后续请求摊销。
