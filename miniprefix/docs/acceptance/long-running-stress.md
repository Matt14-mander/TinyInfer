GPU 运行满足 600 秒；CPU 虽配置最短 180 秒，但继续到至少 128 轮才结束。两组稳态都排除前 10 轮，原始记录不删除。
CPU 启动/预热期间编译过索引工具，所有样本保留。机器未隔离桌面，未锁频；这些是单次运行的观测值，
不是独立重复实验或缓存加速比。原生计时不含 tokenizer、IPC、reference、模型初始化及 JSONL 写盘。

## 实测耗时归因

| 后端 | prefill append | decode append | reuse + publish | 容量准入 | 其余未归因 wall |
|---|---:|---:|---:|---:|---:|
| cpu | 59.176% | 40.640% | 0.0012% | 0.0005% | 0.182% |
| cuda | 43.339% | 54.040% | 0.0392% | 0.0055% | 2.510% |

当前小缓存混合负载的主要时间在模型 append。CUDA append 含同步、传输、cuBLAS/kernel，
不能从本数据进一步断言 attention、GEMM 或同步谁占主导；下一项执行优化前应补更细的 GPU 时间线。
保守预约导致的排队可见于原始 queue_ms，但这不是其相对旧策略的增量延迟，没有 A/B 对照。

## 内存结论与下一步

KV 回收不变量通过，但进程私有提交量并非完全恒定。Engine::seen_ 按契约保留所有历史 ID，
它的生命周期目前无界；本测试不能把全部内存增量归因于 seen_，也不能宣布“无任何内存增长”。
长期常驻部署前需明确历史 ID 去重/保留策略，并在更长 soak 中复测主机内存。

建议顺序：明确有界请求历史策略；对 CUDA append 做 kernel/传输/同步细分并推进批量执行；
在扩大上下文和缓存前优化前缀 key 与 LRU；随后用相同负载做改前/改后及 off/cold/warm 对照。
此项完成持续压力测试和调用级瓶颈测量，不代表整个 Phase 6、COW、抢占或多小时服务验收完成。
