## 结论与限制

多轮 hot 每次 8 个 COW 页、3.955 MiB，正常复制字节和页数在全部旧/新样本中一致。30 层模型的 API 调用数按代码路径从 480 次降为 16 次（每页 60→2）；这不是 GPU 内部 kernel 数的测量。
该负载复制区间中位数 6.925→0.454 ms，约减少 93.4%。旧版三个值为 8.033/6.925/5.102 ms，新版为 0.483/0.369/0.454 ms，三个新值均低于三个旧值。
多轮 hot 的同轮配对 TTFT/TPOT 加速比中位数分别约 1.342×/1.515×，单请求吞吐比约 1.491×。该组 off 对照吞吐比约 1.021×。

其他 off 对照也出现约 1.064×、1.176×、1.154× 的吞吐比；这些路径没有 COW，因此不能把所有端到端差异解释成优化效果。零共享 cold 的配对吞吐比为 0.992×，没有可见提升。
正式测量最长请求约 355.8 ms，没有本任务上一轮测量中的秒级长尾。旧版页内分叉 cold 的一个 profiling 复制区间为 43.009 ms，新版对应组也有 1.371 ms 高点，全部保留。
运行环境是 Windows/WDDM，未锁频或证明排除全部系统活动；6 次正式测量与 3 次 profiling 不足以给出稳定 p99。最稳健的结论是复制阶段显著下降，端到端收益取决于负载且存在波动。

热缓存 prime 成本不计入，测量包含 submit/step IPC 与事件交付，不包含加载、分词、warmup、统计查询和清空缓存。
